# r14-backlight

[English version](README.md)

Держит подсветку клавиатуры ноутбука **Machcreator Genesis R14** включённой в Linux.

Штатно встроенный контроллер (EC) гасит подсветку через 15 секунд без нажатий,
и включается она снова только от нажатия клавиши. Фирменной программы нет, в BIOS настройки тоже нет.
Этот проект — небольшая служба systemd, которая держит подсветку на уровне, выбранном через **Fn+F1**.

> **Статус:** экспериментальный. Пробная запись в EC сработала как ожидалось.
> Службу ещё нужно проверить в реальной работе, особенно после сна.

## Как это работает

Подсветкой клавиатуры целиком управляет прошивка EC. В ACPI (DSDT/SSDT) и WMI интерфейса
для неё нет, поэтому служба читает и пишет регистры EC напрямую через модуль ядра `ec_sys`
(`/sys/kernel/debug/ec/ec0/io`).

| Адрес EC | Что это | Как ведёт себя |
|---|---|---|
| `0x37` | счётчик простоя | +1 каждые 100 мс, обнуляется при любом нажатии клавиши и при Fn+F1. На `0x96` (150 = 15,0 с) останавливается, и подсветка гаснет |
| `0x19` | уровень подсветки | 0 = выкл, 1–4. Fn+F1 переключает по кругу 0→1→2→3→4→0 |
| `0x1a` | копия `0x19` | всегда меняется вместе с ним |

Когда подсветка гаснет по таймауту, уровень не меняется: до порога доходит только счётчик.
Регистра режима или порога таймаута найти не удалось, поэтому служба обнуляет счётчик.

Примерно раз в секунду демон читает `0x19` и `0x37`. Он пишет `0x00` в `0x37` только при трёх условиях одновременно:

- уровень не 0 (подсветка включена через Fn+F1);
- крышка открыта;
- счётчик дошёл до `0x50` (8 с простоя).

Получается примерно одна запись раз в 8 секунд — то же самое EC делает при каждом нажатии клавиши.
На уровне 0 служба ничего не пишет, так что Fn+F1 работает как обычно, в том числе для выключения подсветки.

## Требования

- Machcreator Genesis R14 (плата `N140TRB01_MB`; разработано на BIOS 0.42). На других моделях установщик не запустится.
- Linux с systemd, `python3` и модулем ядра `ec_sys` (есть в стандартном ядре Arch).
- Права root для установки.

## Установка

```sh
sudo bash install.sh
```

Установщик копирует демон в `/usr/local/lib/r14-backlight/`, а unit-файл в
`/etc/systemd/system/r14-backlight.service`, затем включает и запускает службу.

Проверка: включи подсветку через Fn+F1 и не трогай клавиатуру и тачпад больше 15 секунд.
Подсветка должна гореть.

```sh
systemctl status r14-backlight
journalctl -u r14-backlight -b --no-pager | tail
```

## Настройка

Раскомментируй и измени эти строки в `/etc/systemd/system/r14-backlight.service`, затем выполни `systemctl daemon-reload && systemctl restart r14-backlight`:

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `R14_RESET_AT` | `0x50` | обнулять счётчик, когда он дойдёт до этого значения (тики по 100 мс, меньше `0x96`) |
| `R14_POLL` | `1.0` | интервал опроса, секунды |

## Удаление

```sh
sudo bash uninstall.sh
```

## Безопасность

- Запись в EC (`ec_sys write_support=1`) разрешена только пока работает служба.
  При её остановке `ec_sys` перезагружается в режим только чтения. Перезагрузка компьютера в любом случае всё сбрасывает.
- Служба пишет только в регистр `0x37` и только значение `0x00`.
  Регистры температуры, вентилятора, батареи и прочие она не трогает.
- Unit запускается с `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes` и `NoNewPrivileges=yes`.
- Запись в регистры EC — на свой риск. Адреса найдены на одном конкретном ноутбуке и версии BIOS.

## Что ещё не проверено

- Работа после сна. Если после пробуждения подсветка не горит, её должно вернуть нажатие клавиши.
- Включит ли запись `0` уже погасшую подсветку (`0x37 = 0x96`) без нажатия клавиши.

## Структура проекта

```
install.sh, uninstall.sh       установка и удаление службы
src/r14-backlightd.py          демон
systemd/r14-backlight.service  unit-файл systemd
scripts/dump.sh                дамп ACPI-таблиц и снимок EC (только чтение)
scripts/ecwatch.sh             запись изменений регистров EC во времени (только чтение)
scripts/ectest-reset.sh        пробная запись 0x37 := 0x00
NOTES.md                       заметки по исследованию
LICENSE                        MIT
```

Скрипты исследования сохраняют результаты в `data/`, эта папка в репозиторий не входит.
